# Функциональные и нефункциональные требования

## Объём проекта

- Одностраничный свадебный сайт-приглашение.
- Технологическая база будущей реализации: Vite, React, TypeScript.
- Все пользовательские тексты, документация и комментарии — на русском языке.
- Имена файлов, переменных и функций — на английском языке.
- На текущем этапе создаются только спецификации. Исходный код, конфигурация проекта и ассеты не создаются.

## Обязательные секции

1. Полноэкранный вступительный экран с открывающимся конвертом.
2. Hero с именами, датой, текстом-приглашением, фото пары, музыкой и указателем прокрутки.
3. Приветствие гостям.
4. Обратный отсчёт.
5. Программа дня.
6. Две локации.
7. Анкета гостя с условным алкогольным опросом.
8. Лёгкий footer.

Секции дресс-кода, палитры одежды и рекомендаций по нарядам не должно быть ни в интерфейсе, ни в навигации, ни в конфигурации данных.

## Вступительный экран

- Показывается поверх основного сайта при первом входе.
- Закрывает прокрутку и не допускает фокус к содержимому под ним.
- Открывается только по явному клику, тапу, клавишам Enter или Space на доступной кнопке.
- После завершения анимации открывает основной сайт и переводит фокус в hero.
- Поведение повтора задаётся конфигурацией:
  - значение по умолчанию — один раз за вкладку через `sessionStorage`;
  - альтернативный режим — при каждом обновлении.
- При недоступном `sessionStorage` экран работает без падения и показывается снова.
- При `prefers-reduced-motion: reduce` используется короткая смена состояний без сложной 3D-анимации.

## Hero

- Показывает имена `Максим & Елизавета`.
- Показывает реальную фотографию пары в овальной раме.
- Содержит имена пары, дату `29 августа 2026`, короткую фразу и индикатор прокрутки.
- Содержит кнопку музыки с подписью `Гио Пика — Мир`.
- Не пытается автоматически запускать аудио.

## Таймер

- Целевая дата: `29.08.2026 14:35`, часовой пояс `Europe/Moscow`.
- Показывает дни, часы, минуты и секунды.
- После достижения даты заменяется сообщением `Сегодня наш особенный день!`.
- Не показывает отрицательные значения.

## Программа дня

- `14:35 — ЗАГС`.
- `16:00–18:00 — прогулка на трансфере`.
- `18:00 — начало банкета`.
- `23:00 — дискотека`.
- На широком экране допустима горизонтальная линия; на мобильном — вертикальная последовательность.

## Музыка

- Локальный ожидаемый путь: `public/audio/wedding-song.mp3`.
- Начальная громкость: примерно 35%.
- Кнопка переключает play/pause и имеет понятное доступное название состояния.
- Воспроизведение продолжается при прокрутке.
- Если файл отсутствует или не декодируется, кнопка переходит в безопасное неактивное состояние и не вызывает необработанных ошибок.

## Анкета гостя

Поля:

- имя и фамилия — обязательное текстовое поле;
- статус — обязательный одиночный выбор `Буду присутствовать` / `Не смогу присутствовать`;
- комментарий или пожелание — необязательное многострочное поле;
- выбор алкоголя — условный блок с множественным выбором.

Варианты алкоголя:

- Шампанское;
- Белое вино;
- Красное вино;
- Водка;
- Коньяк / виски;
- Без алкоголя;
- Свой вариант.

Логика:

- до выбора статуса блок алкоголя скрыт;
- при `Буду присутствовать` блок мягко раскрывается и становится обязательным;
- при `Не смогу присутствовать` блок скрывается, прошлый выбор очищается и не отправляется;
- `Без алкоголя` взаимоисключается с алкогольными напитками и своим вариантом;
- `Свой вариант` раскрывает обязательное текстовое поле;
- присутствующий гость должен выбрать минимум один вариант либо заполнить свой;
- ошибки показываются рядом с соответствующей группой и связываются с ней доступными атрибутами;
- повторная отправка блокируется на время запроса;
- показываются состояния отправки, успеха и ошибки с возможностью повторить.

## Отправка RSVP

- В комплект будущей реализации входит отдельный код Google Apps Script для записи ответов в Google Sheets.
- Целевая таблица имеет ID `1zinyyqXwi3Ts1-KRHa1xA7NzDvqlHjTzbDmDi9YNBhA`; используется лист `gid=0`.
- Адрес берётся из `VITE_RSVP_SCRIPT_URL`.
- При указанном URL данные отправляются в Google Apps Script.
- При пустом URL используется явный демо-режим с локальным сообщением об успехе.
- Планируемые колонки:
  - Дата отправки;
  - Имя гостя;
  - Статус участия;
  - Алкоголь;
  - Комментарий.
- Нельзя помещать секреты в клиентский код.
- Блок согласия на обработку персональных данных и ссылка на политику не добавляются по решению заказчика.

## Адаптивность

Контрольные ширины: 320, 375, 390, 430, 768, 1024 и 1440 px.

- Нет горизонтального скролла.
- Основной текст не уже комфортной читаемой колонки.
- Минимальная интерактивная область — 44×44 px.
- Декор не перекрывает текст, поля, кнопки и фокус-обводки.
- Поля формы не вызывают нежелательное масштабирование на iOS.
- Карты и фото сохраняют пропорции и не выходят за контейнер.

## Доступность и производительность

- Семантические секции, заголовки по порядку и видимые состояния фокуса.
- Контраст основного текста и контролов соответствует WCAG AA.
- Декоративные изображения скрыты от скринридера; фото пары имеет содержательный alt.
- Управление конвертом, музыкой и формой возможно с клавиатуры.
- Поддерживается `prefers-reduced-motion`.
- Hero-фото загружается приоритетно, второстепенный декор — отложенно.
- Предпочтительны SVG и WebP/AVIF; тяжёлый WebGL не используется.
